FILE-TYPE POLICY
----------------
TXT/MD: safe for research manifests and implementation notes.
MP3/OGG/WAV/FLAC: import into Roblox only after rights and moderation requirements are satisfied.
MP4/WEBM: use as reference or production material outside the runtime repository; Roblox video assets
have their own platform workflow.
ZIP: use for source packs and CI artifacts, then extract only approved content.

WHY BINARY PACKS ARE NOT IN THE RUNTIME TREE
---------------------------------------------
The project is mobile-first and Rojo-managed. Binary packs are better treated as source/reference
materials than as live replicated assets. This keeps cloning, review and CI deterministic.

CURRENT RUNTIME APPROACH
------------------------
- Map geometry: procedural Parts and modular builder functions.
- Combat VFX: client-side generated effects.
- Server combat: authoritative spatial query plus optional line-of-sight raycast.
- Animation: Animator + AnimationTrack when a valid animation ID is configured.
- Fallback animation: local Motor6D transform when a custom animation ID is not configured.
