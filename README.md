# Cursed Collision

Cursed Collision is a continuous Roblox PvP battleground built around server-authoritative combat and character-specific systems.

## Current foundation

- Continuous shared battleground instead of isolated match teleports.
- Server-authoritative M1, Heavy, Dash, Block, Perfect Block, Dodge, Grab, stun, ragdoll and knockback.
- Awakening resource management without a universal energy meter.
- Character framework covering all 24 configured characters.
- Character-specific mechanics and specials.
- Awakening state.
- Domain Expansion and temporary domain environments.
- Domain Clash with exactly four universal clash moves.
- Draws reset the clash instead of selecting a random winner.
- Clash Specials add pressure without bypassing the universal clash rules.
- Perfect Technique Combo tracking.
- One-Time Attack unlock/use rules.
- Server-side action validation, range validation and rate limiting.
- Runtime mobile/PC combat UI.
- Procedural battleground starter map.

## Studio workflow

This repository uses a Rojo-compatible source tree.

1. Install Rojo.
2. Open this repository as the project root.
3. Run Rojo against `default.project.json`.
4. Open a Roblox Studio place and connect Rojo.
5. Play-test in Studio with at least two players to test Domain Clash.

No Roblox Studio execution is performed by GitHub itself. The repository contains the authoritative source that is intended to be synchronized into Studio.

PC:

- Heavy: R
- Dash: Q
- Block: F
- Dodge: E
- Grab: T
- Special: Z
- Character Skill: X
- Awakening: G
- Domain: H
- One-Time Attack: J
- Clash moves: 1, 2, 3, 4

Mobile controls are generated by the client UI.

## Architecture

`ReplicatedStorage`
- Combat
- Characters
- Domains
- DomainClash
- PerfectCombos
- OneTimeAttacks
- Shared

`ServerScriptService`
- CombatServer
- WorldBuilder

The design intentionally keeps universal combat separate from character modules so additional characters do not require rebuilding the combat core.


## Mobile-first CI

The repository is designed so source inspection, structural validation, Rojo builds, and Luau static analysis run in GitHub Actions. This allows the development workflow to stay cloud-first and does not require Roblox Studio on the developer's Android device.

## Verification status

Automated repository validation is performed by GitHub Actions. Roblox Studio gameplay execution, replication behavior, animation fidelity, asset availability, and final publishing remain external validation steps and are marked **NOT VERIFIED** until actually executed in Roblox.
